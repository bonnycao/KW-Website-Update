KeelWorks Design System 2.0

Design System - Foundations

This Foundation guide establishes the visual language for KeelWorks Website 2.0. It defines our brand colors and their meaning, typography, accessible color combinations, buttons, links, spacing, sizing, and other core design decisions. Designers and developers should use these shared tokens and usage rules to create a consistent, inclusive, and recognizable experience across every page.

Color primitives

Raw values preserve the designer’s complete KeelWorks palette. Use these as alias sources; components should use semantic colors.

lightbulb Use For

Creating and maintaining the raw KeelWorks palette; semantic tokens should alias these values.

front_hand Avoid

Applying primitive colors directly to buttons, cards, text, or other components.

straighten Key Rule

Cyan is the core brand family; yellow is the secondary brand accent; plum is tertiary. Preserve consistent hue families.

Use approved pairings, not color alone, to communicate meaning. Samples show intended real-world usage.

WCAG AA: normal text ≥ 4.5:1, large text ≥ 3:1, and meaningful UI boundaries ≥ 3:1. Always verify final combinations and states.

Typography scale & usage guidelines

Raleway gives headings a distinct, optimistic voice. Lato supports readable body copy, labels, captions, and links.

lightbulb Use For

Raleway for display and headings; Lato for body copy, labels, instructions, captions, and links.

front_hand Avoid

Raleway in paragraphs or dense content, and mixing font roles at the same hierarchy level.

straighten Key Rule

Keep heading order semantic. Use 1.2× display, about 1.3× heading, and 1.5× body line height.

Buttons

Three brand tiers, four sizes, and conventional rounded-rectangle buttons across interaction states. Yellow is secondary; plum is tertiary.

Primary · cyan

Main task or progression. One visually dominant primary action per area.

Secondary · yellow

Important alternative or high-visibility campaign action such as Donate.

Tertiary · plum

Supporting actions used selectively; never compete with primary CTAs.

Button corners scale subtly with size: Jumbo 12px, Large 10px, Medium 8px, Small 6px. Recommended scale: Jumbo 64px for hero CTAs; Large 52px for prominent page actions; Medium 44px for everyday actions; Small 36px visually for compact contexts, with a minimum 44 × 44px interactive target. Differentiate sizes through height, horizontal padding, and typography—not height alone.

Button & action hierarchy

One clear primary

Use the cyan primary button for the main next step. Avoid competing primary buttons in the same decision area.

Intentional yellow

Use secondary yellow for Donate and other intentionally emphasized actions, with dark text for contrast.

Supporting plum

Use tertiary plum sparingly. Links are for navigation; buttons initiate actions. Maintain accessible focus and disabled states.

Navigation and inline-link usage

Navigation menus: no underline; hover/focus use bold blue and a visible focus ring. In long-form body copy, add another visual cue such as underline to ensure links are identifiable without relying only on color. Visited colors should not change layout or meaning.

Dimensions

A shared dimension scale supports consistent rhythm, shape, control sizing, and responsive behavior.

lightbulb Use For

Consistent internal padding, content gaps, section rhythm, radii, border widths, icon sizes, and control heights.

front_hand Avoid

Inventing one-off spacing values or separate margin and padding scales.

straighten Key Rule

Use one shared spacing scale. Use rounded-rectangle button corners (6–12px by size); reserve radius/full for pills, tags, avatars, and circular controls.

Elevation

Use elevation sparingly to clarify hierarchy for sticky surfaces, popovers, and dialogs.

lightbulb Use For

Sticky surfaces, menus, popovers, dialogs, and other content that must appear above the page.

front_hand Avoid

Decorative shadows on every card or using elevation instead of spacing and borders.

straighten Key Rule

Core rules

  • Cards: 4 → 2 → 1 columns across desktop, tablet, and mobile
  • Keep readable text lines near 60–75 characters
  • Use 44px minimum interactive targets even when the visual control is smaller
  • Let content determine height; avoid fixed-height text containers

Accessibility & implementation

Functional icons need an accessible name. Hide decorative icons from assistive technology. Icon-only controls need a tooltip and a 44 × 44 px target.

Recommended: Material Symbols Rounded, weight 400, with Fill off by default.

Accessibility

Accessibility is part of the foundation, not a final QA step. Apply these rules to every component and page.

Color contrast

Normal text ≥ 4.5:1. Large text ≥ 3:1. Do not use color alone for meaning.

Keyboard & focus

Every action is keyboard reachable. Use a visible 2px focus indicator.

Targets & spacing

Interactive target ≥ 44 × 44px. Keep space between actions.

Typography

Body copy stays at least 16px where practical. Support 200% zoom without lost content.

Motion

Respect prefers-reduced-motion. Avoid motion essential to understanding.

Content

Use clear labels, meaningful link text, alt text, and logical heading order.
